# Tag recommendations

The main list ranks tags by the linear decision score of an L2-regularized logistic classifier. It shows every tag scoring at least 0.1. When fewer than six qualify, it fills the remaining places with the next highest-scoring classifier candidates and displays their names in a muted color. A tag needs ten ready positives within the media's vision profile and at least one contrasting example. Class-balanced training gives an intercept-only model a baseline of zero. The cutoff has not been calibrated against user feedback. The collapsed Other suggestions list ranks up to ten tags without a usable classifier by the existing centroid rule. Both lists exclude applied tags, rejections and `tagme`.

Each fit includes every usable confirmed positive and explicit rejection. It takes up to four unlabeled items per positive, capped at 256. Sampling follows content hash order within the profile after excluding confirmed labels. All videos contribute one aggregate vector. Sampling creates no database feedback records.

Positives and contrast each receive half of the total objective weight. Within contrast, rejections receive four units per example and weak examples one, with total weak weight capped at total rejection weight when both exist. If there are no rejections, sampled unlabeled examples provide the entire contrast. This keeps the total influence of contrast independent of collection size. Strong regularization and the margin cutoff cannot establish precision for sparse or duplicated examples.

One River maintenance worker fits up to 16 tags per batch. It checks for durable dirty revisions every ten seconds. Edits have a three-second debounce. Collection changes refresh weak samples at most once every six hours. Fits warm-start only within the same profile and configuration version. Each takes a repeatable-read snapshot, releases it before optimization and conditionally publishes against its captured revision. A failed fit leaves the last usable weights available. A rebuild records target revisions and resumes the same targets on retry.

The trainer uses unit-normalized float32 features, double precision arithmetic, L2 strength 0.01, and L-BFGS with eight history entries. Each fit allows 50 major iterations and 150 evaluations each of loss and gradient. Up to 8,192 training rows stay in memory (about 24 MiB of raw features). Larger datasets spill to a temporary file and are read sequentially for each evaluation. These are implementation budgets. End-to-end training latency, peak memory and recommendation quality still need measurement on representative collections.

Older embeddings lack the producing profile fingerprint. They are excluded from both rankings until their profile is known. When all of them came from the current model and preprocessing, Settings provides a one-time option to record that provenance as part of a rebuild. Leave it unchecked for mixed or unknown provenance. New uploads and validated imports record their profile automatically.
